# UI 布局辅助判定（ui_layout_check）

> 独立插件，不动测试主干。分工：**代码管坐标事实，AI 管语义判定。**

## 什么时候调用 `ui_layout_check`（强制触发条件）

**触发词绑定**——只要满足任一条，下结论前必须先调 `ui_layout_check`：

- 你的观察结论或 finding 涉及：**重叠 / 遮挡 / 截断 / 错位 / 挤压 / 布局 / 自适应**
- 用例的预期结果含：**无重叠、无遮挡、无截断、布局完整、自适应、内容完整展示**
- 浮窗 / 分屏 / 无限工作台 / 横竖屏切换后的布局核对

```
判 FAIL 前 → 调它核实坐标事实（两源一致才可判布局异常）
判 PASS 前 → 调它确认排除理由（PASS 的 finding 必须写明排除理由）
跳过调用直接下布局类结论 = 无效判定，必须重判
```

**机制保证**：检测结果自动落盘 evidence 目录的 `layout_check.json`，findings-batch
提交时按它校验一致性——`verdict_hint=FAIL` 却判 PASS 且 actual 未写排除理由 →
**拒绝提交**；布局类断言（expect 含重叠/遮挡/截断/布局等词）但该步骤没跑过检测 →
也拒绝。逃生门 `--skip-layout-gate` 仅限工具异常/证据丢失，正常流程禁用。

调用方式：传 `evidence` 目录路径即可；**不用传包名**（自动对准当前会话登记的被测 App；查其它窗口才用 `package` 覆盖）。

## 解读返回结果的纪律

```
① 返回 tree_blind=true（目标包节点不在视图树里）
   → 浮窗/分屏机型盲区，本结果不可信：
     涉及浮窗/分屏内部布局的判定必须改走 android_vision 看截图，
     提示词固定含「按钮之间是否有任何重叠/遮挡/截断」
② 返回 overlaps 命中
   → 这是确定性坐标事实（谁压谁/压多少）。与截图/视觉判断一致才可判布局异常（FAIL）
   → 业务规则：按钮之间不能有任何重叠（双可点控件 1px 相交即报），无裁量空间
③ 仅**非可点且无文本**的装饰性叠加（角标压图标/悬浮球压内容/遮罩）可排除——
   **可点控件与文本内容之间的重叠不存在「设计性紧凑布局」的排除理由**，
   语义内容（可点或带文本）1px 相交即 BUG，不允许无理由 PASS
④ count=0 且无 tree_blind
   → 视图树层面干净。但自绘内容（SurfaceView/Canvas）不在树里，
     那类问题仍走视觉判定，单源结论需注明
```

## 已知边界（2026-11-23 实测）

- 部分机型 ROM 的 dump 抓不到浮窗/自由窗口节点（`com.zui.recorder` 浮窗整窗缺失实测）——浮窗场景的树检结果**默认不可信**，以 tree_blind 为准
- 全屏遮罩/毛玻璃（宽高 ≥95% 屏）已豁免，不会刷屏误报
- 分析引擎：`<工具层>\tools\layout_check.py`（纯标准库，可独立 CLI 调用做离线回扫）
